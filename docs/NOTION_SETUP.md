# Notion setup

TUF builds its own workspace inside **one page you share with it**. You don't need to
duplicate a template: `tuf setup` (or the `setup` mode of the GitHub workflow) is the
template, and it's safe to run again.

## 1. Create the integration and root page

1. Go to <https://www.notion.so/profile/integrations> and click **New integration**.
   - Type: **Internal**. Workspace: the one you'll use for budgeting.
   - Capabilities: **Read content**, **Update content**, **Insert content**. TUF needs no
     user information and no comment access.
   - Copy the **Internal Integration Secret**. This is `NOTION_API_KEY`.
2. Create an empty page, for example **Budget**.
3. On that page, open **•••**, choose **Connections**, and add your integration. The
   integration can see only this page and what's inside it.
4. Copy the page URL. This is `NOTION_ROOT_PAGE_ID` (a URL or a 32-character id both work).

## 2. Create the workspace

Run `tuf setup` locally, or the **setup** mode of the GitHub workflow. Inside your page it
creates:

| Item | Purpose |
|---|---|
| 📊 **TUF Dashboard** | The visual dashboard (a page) |
| 💳 **TUF Expenses** | One row per Splitwise expense you're part of |
| 🏷️ **TUF Categories** | Categories, subcategories, budgets, your keyword rules, suggestion review |
| 🧳 **TUF Trips** | Trips, trip budgets, linked groups and tags |
| 🎯 **TUF Budgets** | One row per month and budget scope, with actual vs. limit and a gauge |

The nine baseline categories (Dining Out, Groceries, Snacks, Entertainment, Shopping,
Transportation, Stay, Health & Insurance, Other) and their subcategories are created in
**TUF Categories**.

Running setup again creates only what's missing. Sync adds missing properties to existing
databases, but it never deletes or retypes a property you changed. `tuf check` reports
incompatible changes.

## 3. Set your budgets

- **Overall monthly budget:** the `MONTHLY_BUDGET` setting.
- **Category or subcategory budgets:** fill in **Monthly Budget** on the row in
  **TUF Categories**.
- **Trip budgets:** fill in **Budget** on the trip in **TUF Trips**.

Budgets take effect on the next sync. Gauges are green below `BUDGET_AMBER_PCT` (75%),
amber up to `BUDGET_RED_PCT` (90%), red up to 100%, and "Over" above that.

## 4. Teach TUF your habits (optional)

| You do this in Notion | TUF does this |
|---|---|
| Change an expense's **Category** or **Subcategory** | Locks that row (*Category Locked*) and applies the same labels to future expenses with the same description |
| Untick **Category Locked** | Lets TUF categorize the row again |
| Type keywords into **Classification Rules** on a category row (`blue bottle, philz`) | Uses them before any built-in rule or AI |
| Add a row to **TUF Categories** with **Parent** set | Creates a new subcategory. Leave Parent empty for a new primary category |
| Set a suggested subcategory's **Status** to *Active* or *Rejected* | Promotes matching expenses into it, or never suggests it again |
| Add a trip in **TUF Trips** with **Splitwise Groups** or **Tags** | Links matching expenses to the trip |

## 5. The dashboard

Everything **below** the grey callout that starts with *"Generated by TUF"* is rewritten by
TUF when the numbers change. Everything **above** it is yours: add notes, linked views, or
native charts there. Don't edit below the marker, because your changes will be overwritten.

Sections: **Overview** (KPI cards and budget gauges), **Insights**, **Categories**,
**Trends** (charts), **Trips**, **Recurring purchases**, and **Recent expenses**.

### Charts

Notion's Free plan allows **one** native chart per workspace, so TUF renders its charts as
small SVG images and uploads them to the dashboard. Each sync replaces them when the numbers
change. To turn them off, set `DASHBOARD_CHARTS=false`.

> Notion's documentation lists SVG as a supported image type. TUF's chart rendering inside
> Notion has **not yet been visually verified against a live workspace** (see
> IMPLEMENTATION_STATUS.md). If SVGs don't display in your workspace, please open an issue.
> The same numbers are always shown as text and gauges.

### Native views (optional)

`tuf setup --views` (which the workflow's setup mode runs) tries to create, above the marker:

- a native **Monthly spending** column chart (sum of *Spending* by month),
- a **Recent expenses** gallery (Status = Active, newest first),
- a **Trips** gallery.

The Views API is new, and on the Free plan the chart may count as your one chart. If a view
can't be created, setup prints why. To add it by hand:

1. On **TUF Dashboard**, above the marker, type `/linked` and pick **TUF Expenses**.
2. Add a **Chart** view: Column, X axis **Date** grouped by **Month**, Y axis **Spending**
   (Sum).
3. Add a filter **Status is Active**. This filter matters: it excludes settlements, deleted
   rows and rows awaiting an exchange rate.

**Always total *Spending*, never *Total Cost* or *Paid Share*.** *Spending* is your personal
share in your reporting currency. The other columns are kept for auditing.

## 6. Expense columns explained

| Column | Meaning |
|---|---|
| Spending | Your share in the reporting currency. **This is the one to sum.** Empty if no exchange rate was available |
| My Share | Your share in the expense's original currency |
| Paid Share / Owed Share / Net | Raw Splitwise values for you (Net = paid − owed) |
| Type | Expense, Refund, Paid for Others, Reimbursement, Settlement Paid/Received, No Share |
| Status | Active · Deleted (deleted in Splitwise) · Removed (you're no longer part of it) · Needs FX |
| Classification | How the category was chosen: Manual, Rule, Learned, Keyword, Splitwise Category, AI, Fallback |
| Sync Key, Splitwise ID, Account ID, Class Key, Source Updated | Used by TUF for sync. **Don't edit** |

You can hide columns you don't care about. Don't rename or delete the ones TUF uses.
